## 3. 이번 구현의 구체적인 화면 규칙

### 3.1 홈

기본 위치는 왼쪽 위 오늘 할 일, 오른쪽 위 캘린더, 왼쪽 아래 메모, 오른쪽 아래 바로가기다.
기존 2×2 배치와 크기 조절, 사용자 배치 저장, 기본 배치로 복귀를 유지한다.
업데이트 때 사용자의 기존 배치를 강제로 초기화하지 않는다.
캘린더 카드 제목은 특정 날짜에 한정되는 '오늘 일정' 대신 '캘린더'로 표시한다.

### 3.2 캘린더 카드와 날짜 확대

이하 확대 방식은 이번 구현을 위한 설계 해석이다. 사용자가 다른 화면 방식을 요청하면 갱신한다.

- 기본은 현재 월의 달력. 이전 달 / 다음 달 / 오늘 버튼을 제공한다.
- 오늘과 선택 날짜를 색상뿐 아니라 테두리·텍스트·접근성 상태로 구분한다.
- 날짜별 할 일 수 또는 완료/전체 수를 간결하게 표시한다. 작은 칸에 많은 기호를 넣지 않는다.
- 날짜 클릭 → 홈 위에 큰 날짜 상세 대화상자를 연다. 홈 카드를 다른 위치로 옮기거나 배치 설정을 덮어쓰지 않는다.
- 상세 제목 예: `2026년 11월 25일 (수)`. 오늘이면 '오늘'을 덧붙인다. 다른 날짜를 '오늘 일정'이라고 표시하지 않는다.
- 상세에서 이전 날 / 다음 날 / 오늘로 이동할 수 있다.
- 닫기 또는 Esc → 열기 전 보고 있던 월로 복귀하고, 열었던 날짜 버튼으로 포커스를 돌려준다.
- 날짜 상세 내부는 스크롤 가능해야 하며, 작은 창에서도 닫기와 핵심 조작이 접근 가능해야 한다.
- 대화상자 밖으로 Tab 포커스가 빠지지 않게 한다. 배경 카드나 원형 메뉴를 실수로 조작하지 않게 한다.
- 여러 날짜를 빠르게 선택해도 늦게 도착한 응답이 현재 날짜 내용을 덮어쓰지 않아야 한다.

### 3.3 날짜 상세의 데이터와 조작

로컬 달력은 별도 일정 저장소가 아니라 **기존 Task의 날짜별 보기**다.

- 선택 날짜와 `Task.date`가 같은 할 일을 표시한다. 완료한 항목도 별도 구분하여 확인한다.
- `doneAt`은 실제 완료 시각이다. 이것을 예정 날짜인 `date` 대신 사용하지 않는다.
- 날짜 없는 수신함·나중 할 일과 취소 상태 항목은 달력 날짜에 임의로 배정하지 않는다.
- 지난 미완료는 원래 지정 날짜에 남는다. 오늘 할 일 카드의 '지난 할 일' 안내와 달력 표시를 혼동하지 않는다.
- 시간 미지정과 시간 지정 항목을 구분하고, 시간 지정은 시간순으로 정렬한다. 같은 시각에서는 안정적인 기존 순서를 유지한다.
- 빈 날짜는 오류가 아니라 '이 날짜에 등록된 할 일이 없어요' 안내와 추가 동작을 제공한다.
- 날짜별 목록에서 할 일 추가·완료·완료 취소를 지원한다. 날짜 이동·상세 수정은 기존 할 일 편집 흐름을 재사용한다.
- 날짜 상세에서 새 할 일을 추가하면 선택 날짜가 기본이다. 저장 전 실제 저장 날짜를 보여 준다.
- 초기 구현은 제목과 선택 날짜를 명시적으로 전달하는 단순 입력으로 한다. 자연어 입력의 '내일'이 선택 날짜를 암묵적으로 덮어쓰게 만들지 않는다.
- 기존 반복·루틴의 완료 및 날짜 변경 제한을 그대로 적용한다. 새 UI에서 제한을 우회하지 않는다.
- 달력을 탐색하는 것만으로 미래 루틴이나 반복 회차를 DB에 생성하지 않는다. 초기 버전은 저장된 회차만 표시하며, 반복의 미래 전체를 예측해 보여 주는 기능은 후속이다.
- 추가·수정·완료 결과가 오늘 할 일 카드, 날짜 상세, 월간 표시, 할 일 목록에서 일치해야 한다.
- 갱신을 위해 전체 홈을 다시 마운트하여 작성 중인 메모나 바로가기 입력을 지우지 않는다.

### 3.4 Google 일정과의 관계

Google 연동 실패나 미연결이 로컬 달력을 막아서는 안 된다.

- 현재 Google provider는 **오늘 일정만** 제공한다. 임의 날짜의 외부 일정 조회가 있다고 가정하지 않는다.
- 초기 구현은 선택 날짜가 오늘일 때 기존 Google 일정을 별도 'Google 일정' 영역에 읽기 전용으로 표시한다.
- 오늘이 아닌 날짜에 오늘의 Google 일정을 표시하지 않는다. 연결된 경우 다른 날짜의 Google 일정 조회는 아직 지원하지 않는다고 안내한다.
- 미연결 시 로컬 할 일은 정상 사용하며 Google 연결은 부가 동작으로 안내한다.
- 외부 일정 오류는 해당 영역 안에서 이유와 재시도를 표시한다. '일정 없음'으로 실패를 숨기지 않는다.
- 외부 일정은 로컬 Task로 자동 복사하지 않는다. 원본 열기는 기존 main의 ID 기반 검증 경로를 유지한다.
- 원형 메뉴에서 로컬 달력 접근을 제공한다. 기존 Google 웹 열기 동작과 이름을 혼동하지 않고, 저장된 사용자 메뉴 매핑을 일괄 초기화하지 않는다.
- 다른 날짜의 Google 일정 조회와 양방향 일정 편집은 후속 범위다.

### 3.5 바로가기 UI

ATDT에서 차용할 핵심은 **쉽게 찾는 타일, 분명한 실행/편집 구분, 예측 가능한 순서 변경**이다.

- 일반 모드: 반응형 타일 격자. 아이콘, 이름, 링크/파일/폴더 유형을 표시한다.
- 긴 이름·주소가 레이아웃을 깨뜨리지 않아야 한다. 이름과 대상은 툴팁 및 접근 가능한 이름으로 확인할 수 있어야 한다.
- 편집 모드: 이름 수정·순서 변경·삭제 조작을 명시적으로 제공한다. 편집 중 타일 클릭으로 외부 앱이 실행되지 않는다.
- 추가 버튼은 쉽게 찾을 수 있게 유지한다. 링크와 파일/폴더 선택의 기존 흐름을 재사용한다.
- 초기에는 기존 데이터 모델과 전체 순서를 유지한다. 사용자 그룹은 별도 후속 작업으로 분리하며, 유형별 임의 그룹으로 사용자 순서를 깨뜨리지 않는다.
- 빈 상태에서 추가 방법을 안내한다. 조회 실패를 빈 목록으로 표시하지 않는다.
- 저장·삭제·이동 실패는 카드 안에서 알려 주고, 입력값과 기존 항목을 보존한다.
- 저장 중 반복 클릭으로 동일 항목이 중복 생성되지 않게 한다.
- 기존 URL 검사, 파일 선택, 실행 파일 승인, ID 기반 실행을 유지한다.
- 인터넷 파비콘 수집, 연결 상태 주기 조회, 자유로운 아이콘 업로드는 이번 범위에 추가하지 않는다.

## 4. 안정성 원칙

1. 코어 데이터의 원본은 하나다. 캘린더용 복제 저장소를 만들지 않는다.
2. 새 조회는 필요한 기간을 조회한다. 모든 보기를 반복해서 읽고 합치는 방식으로 달력을 구현하지 않는다.
3. 읽기 실패, 저장 실패, 빈 결과, 로딩 상태를 구분한다.
4. 실패 후 재시도 가능해야 하며 성공하지 않은 동작을 성공한 것처럼 표시하지 않는다.
5. 저장 중 재클릭 방지, 오래된 응답 무시, 화면 닫힘 이후 갱신 방지를 필요한 곳에 적용한다.
6. 기존 사용자 데이터·배치·바로가기·승인 상태를 유지한다.
7. 작성 내용이 있는 상태에서 닫기나 날짜 이동을 하면 내용 유지 또는 명시적인 버리기 확인을 제공한다. 저장 실패 시 자동으로 닫지 않는다.
8. 외부 서비스 실제 호출은 자동 테스트에 넣지 않는다. 가짜 provider와 임시 DB를 사용한다.
9. 실제 계정·사용자 vault·개인 데이터는 검증용 샘플로 사용하지 않는다.
10. 소스 변경, 테스트, 실제 화면 확인 결과를 별도로 보고한다. 화면 캡처만으로 클릭 흐름 통과를 주장하지 않는다.

## 6. Claude Code 작업 단위

### 첫 작업: C1만 구현

**목표:** Google 미연결 상태에서도 홈 월간 달력이 보이고, 날짜 클릭으로 해당 날짜의 저장된 할 일을 확대해서 읽을 수 있다.

1. 현재 코드·관련 계약을 읽고 필요한 API 변경을 먼저 짧게 제시한다.
2. 날짜/월 조회의 정상·빈 결과·잘못된 입력·DB 실패 테스트를 먼저 작성한다.
3. 코어 Task 조회 → 검증된 IPC → preload → UI 순서로 연결한다. DB 스키마 변경은 필요성을 증명하기 전에는 하지 않는다.
4. 날짜 확대/복귀, 키보드, 비동기 응답 역전, Google 실패 격리 테스트를 작성한다.
5. 오늘 일정만 제공하는 Google provider의 한계를 정직하게 UI에 반영한다.
6. 관련 테스트, 타입 검사, 전체 테스트, 빌드를 수행한다.
7. 샘플 데이터로 화면을 확인하고 결과를 `docs/acceptance/dev2-home.md`에 추가한다.
8. C1 완료 후 Codex 검토를 받는다. C2/S1을 같은 변경에 섞지 않는다.

### 두 번째 작업: C2

C1 통과 후 날짜별 추가·완료·완료 취소·기존 편집 연결을 구현한다.
작성 내용 보호, 반복/루틴 제한, 중복 클릭, 다른 카드와의 일치 검증을 포함한다.

### 세 번째 작업: S1

C2 통과 후 바로가기 타일과 편집 모드를 구현한다.
기존 실행·승인·순서·취소 동작을 보존하고 실제 외부 프로그램을 여는 자동 테스트는 금지한다.

### 검토에 필요한 보고

- 작업 ID, 기준 및 결과 커밋(미커밋이면 그 사실), 변경 파일.
- 신규 테스트와 각각의 사용자 시나리오.
- 실행 명령, 성공/실패, 테스트 수.
- 실제 화면 확인 항목, 캡처 또는 재현 절차, 미확인 항목.
- 계약/API 변경과 데이터 마이그레이션 유무.
- 남은 문제. 실패를 숨기거나 다음 항목으로 우회하지 않는다.

push·main 병합·릴리스는 이 문서의 구현 지시에 포함하지 않는다.
