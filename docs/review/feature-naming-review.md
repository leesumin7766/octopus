# 기능·이름 기준 검토 (2026-11-27)

> **대체됨:** Codex 검토와 합친 [usability-proposal.md](usability-proposal.md) 가 최신이다. 이 문서는 근거 자료로 남긴다.

Claude Code / `dev` 브랜치 `126b3c7` 기준. 코드와 화면 문구(`renderer/i18n/ko.ts`)를 전부 읽고 정리했다. **아직 아무것도 고치지 않았다.** 6장의 결정이 나면 그에 맞춰 고친다.

사용자 지적:

- 모든 기능과 기능명에 기준이 없다. 그래서 비슷한 기능이 다른 이름으로 중복 동작한다.
- 할 일을 추가하고 끝내는 흐름이 쓰기 불편하다.
- 메모 입력과 할 일 입력처럼 비슷한 기능의 화면이 이유 없이 다르다.

---

## 1. 결론

문제의 뿌리는 세 가지다.

1. **같은 개념에 이름이 여럿.**
   - '캘린더/달력'
   - '체크리스트/루틴/데일리 체크리스트'
   - '메모'(메모 기능)와 '메모'(할 일의 설명 칸)
   - '취소'의 세 가지 뜻
2. **같은 동작을 화면마다 따로 만들었다.**
   - 할 일 추가 입력이 3종, 메모 입력이 3종이다.
   - 체크했을 때의 동작이 4종이다.
3. **내부 구조가 화면에 그대로 나왔다.**
   - '보관함(수신함/예정/나중에)'을 사용자가 직접 고른다.
   - 날짜와 보관함이 맞지 않으면 오류가 난다.
   - 루틴 항목과 반복 할 일이 비슷한데 따로 논다.

그래서 먼저 **기준(용어 사전 + 동작 규칙 + 부품 규칙)** 을 정하고, 모든 화면을 그 기준에 맞춘다. 기준은 승인되면 `docs/UI_STANDARD.md` 로 옮겨 CLAUDE.md 처럼 매 작업 전에 읽는 규칙으로 삼는다.

## 2. 지금 상태: 같은 일을 하는 곳들

### 2.1 할 일 추가 — 8곳, 입력 방식 3종

| # | 어디서 | 입력 방식 | 자연어(내일·3시·#·!) | 추가 후 |
|---|---|---|---|---|
| 1 | 할 일 탭 맨 위 | 빠른 입력(QuickInput) | 됨 | 목록에 나타남 |
| 2 | 홈 '오늘 할 일' 카드 | 같은 빠른 입력 | 됨 | 날짜가 오늘이 아니면 카드에 안 보임(알림 없음) |
| 3 | 원형 메뉴 '할 일 추가' | 대화상자 안의 같은 빠른 입력 | 됨 | "할 일을 추가했어요" |
| 4 | 홈 달력 → 날짜 상세 | **제목 칸 + 시각 칸(별도 부품)** | **안 됨** — "내일 3시"라고 쓰면 제목이 그대로 "내일 3시" | 그 날짜에 추가 |
| 5 | 달력 탭 오른쪽 | 4와 같은 부품 | 안 됨 | 그 날짜에 추가 |
| 6 | 메모 → '할 일로 만들기' | 버튼 | — | "할 일 탭에서 확인해 보세요" |
| 7 | 수신함 '들어온 후보' → '수신함에 넣기' | 버튼 | — | 수신함으로 |
| 8 | 지시하기 `add_task` | 대화 + 승인 | LLM 이 해석 | 승인 후 |

(루틴은 정해진 요일에 오늘 할 일을 저절로 만든다. 9번째 경로다.)

### 2.2 할 일 끝내기(체크) — 동작 4종

| 어디서 | 체크하면 | 되돌리기 | 체크 해제 |
|---|---|---|---|
| 할 일 탭(모든 보기) | 0.35초 흐려진 뒤 **사라짐** | 아래 알림 6초 [되돌리기] | 사라져서 못 함('완료' 보기로 가야 함) |
| 홈 '오늘 할 일' 카드 | 0.35초 흐려진 뒤 **사라짐** | **없음** | 못 함 |
| 날짜 상세·달력 탭 | 줄 긋고 **그 자리에 남음** | 다시 누르면 해제 | 됨 |
| 체크리스트 화면 | 줄 긋고 **그 자리에 남음** | 다시 누르면 해제 | 됨 |

**같은 루틴 항목이 세 곳에 나오고, 세 곳의 체크 동작이 다르다.** 할 일 탭 '오늘', 홈 카드, 체크리스트 화면이다. 홈 카드에서 실수로 체크하면 되돌릴 방법이 화면에 없다.

### 2.3 그만두기·지우기

할 일 상세 패널 아래쪽에 버튼이 이렇게 있다: **[저장] [닫기] [취소] [삭제]**

- 여기서 **[취소]는 "편집 취소"가 아니라 "이 할 일을 안 하기로 함"(status=canceled)** 이다.
- 취소한 할 일은 **어느 보기에도 나오지 않는다**(수신함·오늘·예정·나중에·완료 모두). 사실상 '되돌릴 수 있는 삭제'인데 되찾을 화면이 없다.
- 날짜 상세에도 취소·삭제가 따로 있다.

### 2.4 메모 쓰기 — 3곳, 모양·키 모두 다름

| 어디서 | 모양 | 저장 키 |
|---|---|---|
| 메모 화면 | 3줄 입력칸(옛 회색·남색) + 아래 작은 [저장] | Ctrl+Enter |
| 홈 메모 카드 | 한 줄 입력칸 | Enter |
| 원형 메뉴 '메모 쓰기' | 대화상자 여러 줄 입력칸 | Ctrl+Enter |
| (참고) 지시하기 입력 | 여러 줄 | **Enter 보내기 · Shift+Enter 줄바꿈** |

### 2.5 '오늘'을 보는 곳 — 4곳

할 일 탭 '오늘' 보기 · 홈 '오늘 할 일' 카드 · 홈 달력의 오늘 날짜 상세 · 달력 탭의 오늘. 보이는 내용(지난 할 일 포함 여부, 완료 항목 표시)과 체크 동작이 서로 다르다.

### 2.6 반복 — 2가지 체계

| | 반복 할 일 | 루틴(체크리스트) |
|---|---|---|
| 만드는 곳 | 할 일 상세 > 반복, 또는 빠른 입력 "매주 월" | 체크리스트 화면 |
| 고를 수 있는 것 | 매일/매주/매월/매년 + N마다 + 요일·날짜 | 요일만 |
| 못 했을 때 | 남아서 '지난 할 일'로 쌓임 | 그날 "못 함"으로 기록만 남고 사라짐 |
| 기록 | 완료 보기 | 최근 14일 표 |
| "3주마다 1주, 평일만" | 상세 패널에서 됨(매주·3주마다·월~금). 빠른 입력은 못 알아들음 | 안 됨 |

사용자 입장에서 둘의 차이는 **"못 하면 남기느냐 넘기느냐"** 하나다. 그런데 화면·이름·설정 방법이 전부 따로다.

### 2.7 디자인이 두 벌

- 지금 디자인(따뜻한 회색 바탕, `bg-page`·`ink`·`accent`): 홈·할 일·달력·Arms 일부.
- 옛 디자인(Tailwind `slate`/`indigo` 그대로): **메모 화면, 체크리스트 화면**, 오류 띠, 일부 확인 창.

## 4. 기준안

### 4.1 용어 사전 (화면에는 이 이름만 쓴다)

| 개념 | 정할 이름 | 비고 |
|---|---|---|
| 할 일 | **할 일** | |
| 할 일 안의 설명 | **설명** | '메모'와 분리 |
| 메모 | **메모** | 메모 기능 하나에만 |
| Octopus 자체 달력 | **달력** | 홈 카드 제목도 '달력' |
| 바깥 일정 | **Google 캘린더 / Google 일정** | 제품 이름은 그대로, 표기 통일 |
| 매일 하는 습관 | **루틴** (오늘 화면에서는 '오늘 루틴') | '체크리스트'는 쓰지 않음. 결정 필요(6장 D2) |
| 날짜 지난 미완료 | **지난 할 일** | 줄이지 않음 |

| 동작 | 이름 | 쓰지 않는 말 |
|---|---|---|
| 새로 만듦 | **추가** | 쓰기, 넣기, 만들기 |
| 고친 것을 저장 | **저장** | |
| 고치기 시작 | **편집** | 수정 |
| 영구히 없앰 | **삭제** (확인 후) | 지우기 |
| 대화상자·패널 닫기 | **닫기** | |
| 하던 입력을 그만둠 | **취소** | — 이 뜻으로만 |
| 할 일을 안 하기로 함 | **안 하기** | 취소 |
| 알림을 잠시 치움 | **닫기** | 나중에 |
| 배치 모드 끝 | **배치 끝** | 완료 |
| 들어온 할 일 받기/버리기 | **추가 / 버리기** | 수신함에 넣기, 무시 |

### 4.3 동작 규칙

1. **할 일 추가는 한 부품.** 할 일을 적는 칸은 어디서나 같은 빠른 입력(QuickInput)이다. 모양, 자연어 해석, '알아들은 것' 줄, [추가] 버튼이 모두 같다.
   - 날짜 상세·달력 탭에서는 "날짜를 안 쓰면 이 날짜"만 다르다.
   - 시각 칸을 따로 두지 않는다. "3시"라고 쓰면 된다.
2. **글을 적는 칸의 키는 하나.**
   - Enter 는 저장(보내기)이다.
   - Shift+Enter 는 줄바꿈이다(여러 줄이 되는 칸만).
   - 한글 조합 중 Enter 는 무시한다.
   - 지시하기·메모·할 일 모두 같다.
3. **체크는 어디서나 같다.**
   - 누르면 줄이 그어지고 그 목록의 아래 **'완료 n개'** 묶음으로 내려간다. 묶음은 접혀 있다.
   - 다시 누르면 되돌아온다. 사라지지 않으므로 되돌리기 알림은 필요 없다.
   - 목록 위에는 '남은 n / 전체 m' 을 보여 준다.
4. **안 하기·삭제.**
   - '안 하기'는 줄 그은 회색으로 '완료' 보기에 함께 보인다(되살리기 가능).
   - '삭제'만 영구이고, 반드시 확인한다.
5. **행 동작은 마우스를 올렸을 때만.** 편집·삭제·옮기기는 마우스를 올리거나 키보드로 들어갔을 때 보인다. 제목을 누르면 편집이다.
6. **확인 창은 한 모양.**
   - 행 바로 아래 작은 띠에 "○○을(를) 삭제할까요?"를 띄운다.
   - 버튼은 [삭제] [취소] 순서다.
7. **설명문 금지.**
   - 안내는 placeholder 한 줄과 툴팁으로 한다. 빈 화면 문구는 한 문장이다.
   - 오류 문구만 다음 행동을 알려 준다(CLAUDE.md 5장).
8. **내부 개념을 고르게 하지 않는다.** '보관함'은 화면에서 없앤다.
   - 날짜가 있으면 예정, 없으면 날짜 없음이다.
   - '언젠가'는 날짜 없음 안의 표시 하나로만 둔다(6장 D1).

### 4.4 부품·디자인 규칙

- 입력: `QuickInput` 하나(할 일), `NoteInput` 하나(메모·지시하기, 같은 상자 모양에 줄 수만 늘어남).
- 할 일 한 줄: `TaskRow` 하나. 홈 카드, 할 일 탭, 날짜 상세, 루틴 모두 같은 줄을 쓴다(체크 동작이 같아짐).
- 색·글꼴은 `index.css` 의 토큰만 쓴다(`bg-page`, `ink`, `accent`, `line` …). `slate-*`, `indigo-*` 를 직접 쓰지 않는다. 검사 테스트를 하나 둔다.
- 새 화면·새 문구를 만들 때는 4.1~4.3 표를 먼저 본다. 표에 없는 이름이 필요하면 표에 먼저 추가한다(사용자 승인).
