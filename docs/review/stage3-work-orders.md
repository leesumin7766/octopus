## P6b 업데이트 설치 전 쓰던 내용 확인 (1단계 남은 사항)

- **파일:** `src/renderer/settings/UpdateSection.tsx`, `src/renderer/notices/NoticeBell.tsx`(설치 버튼이 있는 곳), `src/renderer/leaveGuard.tsx`(읽기만 — 이미 있는 `isDirty` 를 쓴다)
- **지금:** [다시 시작해서 설치]는 쓰던 내용(할 일 상세 편집, 메모 초안, 입력칸 글)이 있어도 바로 재시작한다.
- **할 일 (기준 3장 7):** 설치를 누를 때 떠나기 보호에 쓰던 내용이 있으면 먼저 묻는다(같은 `UnsavedStrip` 글·모양: 버리기 / 계속 쓰기). [계속 쓰기]면 설치하지 않는다. 쓰던 내용이 없으면 지금처럼 바로 설치.
- **끝 기준:** 메모 초안이 있을 때 설치 → 묻는다 → 계속 쓰기면 `update.install` 이 불리지 않는다. 버리기면 불린다. 초안이 없으면 바로 불린다. 알림 목록·설정 두 곳 모두.

## N1~N3 문구 통일

- **파일:** `src/renderer/i18n/ko.ts` 중심. 문구 키 이름이 바뀌면 쓰는 곳도. 시험의 기대 문구.
- **할 일:** 기준 1장(용어)·2장(동사) 표대로 화면 문구를 바꾼다.
  - 할 일의 긴 글 칸: '메모' → **설명**
  - '캘린더'는 Octopus 자체 달력이면 **달력**(Google 쪽은 'Google 캘린더' 유지)
  - '루틴', '데일리 체크리스트', '오늘의 체크리스트' → **체크리스트** / **체크리스트 항목**(배지 포함)
  - '취소'(할 일 안 하기)는 **안 하기 / 안 하기로 함**. '취소'는 입력·확인을 그만둘 때만
  - '후보' → **들어온 할 일**
  - 동사: 편집/수정 → **편집**(시작)·**저장**(끝), 삭제/지우기 → **삭제**, 추가/쓰기/넣기 → **추가**
  - 배치 모드의 '완료' → **배치 끝**, 알림 미루기의 '나중에'가 '나중에' 보기와 헷갈리면 **다시 알림** 처럼 다른 말
- 쓰지 않는 문구 키(예: `arms.intro`, `arms.auth`, F1 뒤 남은 `home.localCalendar.addTimeLabel`·`addButton`, F5 뒤 남은 `fieldErrors.bucket` 등)는 지운다. 남은 키가 정말 안 쓰이는지 검색해서 확인.
- 기능·동작은 바꾸지 않는다. 문구만.
- **끝 기준:** `ko.ts` 와 화면 코드에 '루틴'·'캘린더'(Google 제외)·'후보'·'수정'·'지우기'가 화면 문구로 남지 않는다(코드 주석·변수 이름은 상관없음). 이를 검사하는 시험 하나(ko.ts 값 전체를 훑어 금지어가 없는지)를 붙인다. 바꾼 문구 목록을 보고에 표로.

## N5 옛 색 정리 + 토큰 검사

- **파일:** `src/renderer` 의 `slate-*`·`indigo-*`·`emerald-*` 등 Tailwind 기본 색을 쓰는 곳(메모·체크리스트·루틴 폼·상세 패널·할 일 탭 등). `src/renderer/index.css` 의 토큰을 쓴다(`bg-page`, `text-ink`, `border-line`, `accent`, `accent-strong` 등 — 이미 쓰는 화면을 참고).
- **할 일:** 옛 색을 같은 뜻의 토큰이나 주변 화면과 같은 값으로 바꾼다. 배치는 바꾸지 않는다. 경고·위험 색(빨강·주황)은 의미가 있으면 남겨도 되지만, 남긴 것은 보고한다.
- 검사 시험: `src/renderer/**/*.tsx` 에 `slate-`·`indigo-` 가 없음을 확인하는 시험.
- **끝 기준:** 검사 시험 통과. `npm run capture`(README 참고)로 메모·체크리스트·할 일 상세 화면 캡처를 찍어 `.captures/` 에 두고 경로를 보고.

## N4 메모 입력 세 곳 맞추기

- **파일:** `src/renderer/memos/MemosScreen.tsx`(새 메모·편집), `src/renderer/home/cards/MemoCard.tsx`(빠른 메모), 원형 메뉴의 메모 쓰기 대화상자(`src/renderer/home/QuickDialogs.tsx` 쪽)
- **지금:** 메모 화면 Ctrl+Enter, 홈 카드 Enter, 원형 메뉴 Ctrl+Enter 로 저장 키·모양이 다르다.
- **할 일 (기준 3장 1·2):** 한 줄 입력(홈 카드)은 Enter 저장, 여러 줄(메모 화면·원형 메뉴 대화상자·편집)은 Enter 줄바꿈 + Ctrl/Cmd+Enter 저장 + 늘 보이는 [저장] 버튼. 여러 줄 입력은 공용 부품 하나(예: `src/renderer/ui/MultilineInput.tsx`)로 모아 같은 상자 모양·같은 키·한글 조합 중 Enter 무시·저장 중 재요청 막기(P5 동작 유지). 각 칸에 접근성 이름.
- **끝 기준:** 세 곳에서 키·버튼이 기준대로. P5 검증 시험(저장 중복 방지·입력 보존)이 그대로 통과.

## N6 행 '⋯' 버튼

- **파일:** `src/renderer/tasks/TaskRow.tsx`, 완료 보기의 '안 하기로 함' 행([다시 열기]), `src/renderer/memos/MemosScreen.tsx` 의 메모 행 동작
- **지금:** 행 동작이 마우스를 올릴 때만 보인다(키보드 포커스로는 보임). 터치로는 들어가기 어렵다. P2 의 [다시 열기]는 늘 보인다.
- **할 일 (기준 3장 10):** 행마다 늘 보이는 '⋯'(더보기) 버튼 하나. 누르면 그 행의 동작(할 일: 편집 열기·나중에로·안 하기·삭제 / 안 하기로 함: 다시 열기 / 메모: 편집·고정·할 일로 만들기·삭제)을 메뉴로. 키보드로 열고 화살표·Esc 로 다룰 수 있게(`role="menu"`). hover 로 보이는 기존 버튼은 그대로 둬도 된다. [다시 열기]는 ⋯ 안으로 옮기고 hover 에도 보이게.
- 삭제는 지금처럼 확인 후.
- **끝 기준:** 마우스 없이 Tab·Enter·화살표만으로 할 일 '안 하기', 메모 '할 일로 만들기', 안 하기로 함 '다시 열기'를 할 수 있다. ⋯ 버튼마다 접근성 이름("○○ 더보기").
