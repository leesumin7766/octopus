## P4 설정 저장 확인

- **파일:** `src/renderer/settings/useSetting.ts` (+ 이를 쓰는 곳에 오류를 보여 줄 최소한의 연결)
- **지금:** `persist` 가 `settings.set` 결과를 보지 않는다. 실패해도 화면 값은 저장된 것처럼 남는다.
- **할 일:**
  1. `persist` 가 결과를 확인한다. 실패하면 훅이 `error`(또는 비슷한 상태)를 내놓고, 다시 시도할 함수를 준다.
  2. 저장 요청이 여러 번 겹치면 **마지막 요청의 값**이 이긴다. 먼저 보낸 요청의 늦은 응답이 화면 값이나 오류 상태를 덮으면 안 된다.
  3. 오류는 쓰는 화면에 짧게 보여 준다. 대상은 원형 메뉴 설정, 홈 배치, 메뉴 접힘이다. 예: "설정을 저장하지 못했어요. [다시 시도]". 메뉴 접힘처럼 보여 줄 자리가 마땅치 않으면 조용히 다시 시도하지 말고, 화면 값을 저장된 값으로 되돌리는 것도 허용한다. 택한 방식을 보고한다.
- **끝 기준:**
  - `settings.set` 이 실패하면 사용자가 알 수 있고, 다시 시도하면 저장된다.
  - 두 번 연달아 바꿨을 때 첫 응답이 늦게 와도 최종 값은 두 번째 값이다.
  - 성공 흐름은 지금과 같다(기존 테스트 통과).

- **파일:** `src/renderer/update/useUpdate.ts`, `src/renderer/notices/NoticeBell.tsx`, `src/renderer/settings/UpdateSection.tsx`, `ko.ts`

  - [다시 시도]가 같은 동작을 다시 부른다.
  - 성공하면 오류가 사라진다.

## P1 쓰던 내용 보호 (떠나기 보호)

- **파일:** `src/renderer/App.tsx`, `src/renderer/tasks/TasksScreen.tsx`, `src/renderer/tasks/DetailPanel.tsx`, `src/renderer/memos/MemosScreen.tsx`, 새 파일 하나(예: `src/renderer/leaveGuard.tsx`), `ko.ts`
- **지금:**
  - `App` 의 `<main key>` 가 할 일·메모 화면에서 `dataVersion` 이다. 지시하기 등으로 데이터가 바뀌면 화면이 통째로 다시 그려져 초안이 사라진다.
  - 할 일 탭은 상세 패널의 `onDirtyChange` 를 연결하지 않았다. 그래서 다른 할 일을 누르거나 닫으면 편집이 경고 없이 사라진다.
  - 왼쪽 메뉴로 다른 화면에 가도 묻지 않는다.
- **할 일:**
  1. `App` 의 `<main key>` 를 화면 이름으로만 정한다(`key={screen}`). 할 일·메모·체크리스트·그 밖의 화면은 홈·달력처럼 `useDataChanged` 로 스스로 다시 읽는다. **다시 읽어도 쓰던 입력과 편집 상태는 유지한다.**
  2. 할 일 탭: 상세 패널이 dirty 일 때 다른 할 일 선택·패널 닫기를 하면 먼저 묻는다(버리기 / 계속 쓰기). 문구·모양은 `DayDialog` 의 확인 띠(`m.editDiscardTitle`, `m.discardYes`, `m.discardNo`)와 같게 한다.
  3. 메모 화면: 새 메모 초안이나 편집 중인 메모가 있을 때 다른 메모 편집을 시작하면 먼저 묻는다.
  4. 화면 이동 보호: 작은 공용 장치를 만든다(예: `useLeaveGuard(dirty)` 로 등록, `App.navigate` 가 확인). 등록된 화면에 쓰던 내용이 있으면 왼쪽 메뉴·원형 메뉴로 다른 화면에 가기 전에 앱 안 확인 창으로 묻는다. `window.confirm` 은 쓰지 않는다. 할 일 탭(상세 편집, 빠른 입력 글), 메모 화면(초안·편집), 홈의 날짜 상세에 연결한다.
- **끝 기준:**
  - 할 일 상세 편집 중 데이터 변경 이벤트(`notifyDataChanged`)가 와도 편집 내용이 남는다. 메모 초안도 같다.
  - 편집 중 다른 할 일 클릭·닫기 → 묻고, [계속 쓰기]면 그대로, [버리기]면 이동한다.
  - 메모 초안·편집 중 메뉴로 다른 화면 → 묻는다. 쓰던 게 없으면 묻지 않고 바로 간다.
  - 기존 테스트가 통과한다(동작이 바뀐 테스트는 새 기대에 맞게 고치고 보고한다).

## P2 '안 하기로 함' 되찾기

- **파일:** `src/renderer/tasks/TasksScreen.tsx`, 필요하면 `src/main/core/tasks/taskRepository.ts` 와 IPC(목록 조회에 canceled 를 볼 방법이 없으면), `ko.ts`
- **지금:** 상세 패널의 [취소](status=canceled)를 누르면 어느 보기에도 안 나온다. 되돌리기는 6초뿐이다.
- **할 일:**
  1. 상세 패널의 [취소] 버튼 이름을 **[안 하기]** 로 바꾼다. 도움말은 "안 하기로 한 할 일은 완료 보기에서 다시 열 수 있어요." 되돌리기 알림 문구도 맞춘다.
  2. '완료' 보기 위에 [완료 | 안 하기로 함] 거르기를 둔다. '안 하기로 함'에서는 canceled 할 일을 끝난 날짜별로 보여 주고, 행마다 [다시 열기] 로 open 으로 되돌린다.
  3. 완료 수(왼쪽 보기 수, 달력 ●◐○, '이 달 완료')에는 canceled 를 넣지 않는다.
  4. 데이터 조회를 바꾸면 `docs/contracts/` 의 IPC 계약과 다를 수 있다. **계약 문서를 바꿔야 하면 먼저 멈추고 보고한다.** 기존 조회만으로 되면 그대로 쓴다.
- **끝 기준:**
  - 안 하기 → 6초 지난 뒤에도 → 완료 보기의 '안 하기로 함'에서 보이고 → 다시 열기 → 원래 보기에 돌아온다.
  - 앱을 다시 그려도(재마운트) 찾을 수 있다.
  - 완료 수에 들어가지 않는다.
