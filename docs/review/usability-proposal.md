## 1. 결론

- 핵심 문제는 **추가 → 확인 → 편집 → 완료 → 복구** 흐름이 끊기는 것이다. 같은 할 일인데 화면마다 결과와 되돌리는 법이 다르다.
- 이름·디자인이 제각각이라 완성도가 떨어져 보이는 것도 사실이다. 고치는 비용이 작으므로 흐름 작업과 나란히 진행한다.
- 내용이 사라지거나 저장됐다고 믿었는데 안 된 문제(2.1)가 가장 먼저다.
- 보기 합치기, 루틴·반복 합치기, 기록 탭처럼 모델이나 범위가 바뀌는 일은 **이번에 하지 않고** 따로 설계한다.

## 2. 문제 목록

### 2.1 데이터·실수 보호 (높음)

| # | 현상 | 사용자 영향 |
|---|---|---|
| P1 | 할 일 탭은 상세 패널의 '편집 중' 신호를 받지 않는다. 그래서 다른 항목을 누르거나 닫으면 그냥 넘어간다. 또 할 일·메모 화면은 데이터가 바뀔 때마다 통째로 다시 그려진다(`App.tsx` 의 `key={dataVersion}`) | 쓰던 편집·메모 초안이 경고 없이 사라짐 |
| P2 | '취소'(canceled)한 할 일은 어느 보기·달력에도 안 나온다. 되돌리기는 6초뿐이다 | 6초 뒤에는 되찾을 길이 없음 |
| P3 | 홈 '오늘 할 일' 카드에서 체크하면 사라지고, 되돌리기가 없다. 루틴 항목도 이 카드에 나온다 | 실수 체크를 홈에서 복구 못 함 |
| P4 | 설정 저장(`useSetting.persist`)이 결과를 보지 않는다 | 화면 배치·원형 메뉴가 저장된 줄 알았는데 다시 켜면 돌아갈 수 있음 |
| P5 | 홈 메모 카드·메모 화면의 저장이 저장 중 재요청을 막지 않는다. 응답이 오면 그사이 새로 쓴 글까지 지운다 | 메모 중복 생성, 새 입력 유실 |
| P6 | 업데이트 확인·받기·설치가 실패해도 아무 표시가 없다(`useUpdate`) | 눌러도 반응이 없는 버튼 |

### 2.2 할 일 흐름 (높음~보통)

| # | 현상 | 사용자 영향 |
|---|---|---|
| F1 | 할 일을 넣는 곳은 8곳인데, 입력 방식이 3가지다. 날짜 상세·달력 탭은 자연어를 못 알아듣는다("내일 3시"가 제목이 됨) | 같은 칸처럼 보이는데 결과가 다름 |
| F2 | 체크했을 때 동작이 4가지다(아래 표) | 화면마다 결과·복구가 다름 |
| F3 | 홈에서 "보고서"(날짜 없음 → 수신함)나 "내일 보고서"를 넣으면 오늘 카드에 안 보인다. 안내도 없다 | 저장됐는지 모름 |
| F4 | 홈 할 일 제목·메모 첫 줄은 눌러도 아무 일이 없다. '메모 → 할 일로 만들기' 뒤에도 그 할 일로 가는 길이 없다 | 다음 작업으로 못 이어 감 |
| F5 | 할 일 상세에서 '보관함'(수신함/예정/나중에)을 직접 고른다. 날짜와 맞지 않으면 오류가 난다 | 내부 규칙을 사용자가 맞춰야 함 |
| F6 | 할 일 탭에 검색이 없다(메모에는 있음) | 많아지면 못 찾음. AI 검색은 키 없는 사용자에게 대안이 아님 |

| 어디서 | 체크하면 | 복구 |
|---|---|---|
| 할 일 탭 | 0.35초 뒤 사라짐 | 6초 되돌리기 |
| 홈 '오늘 할 일' | 0.35초 뒤 사라짐 | **없음** |
| 날짜 상세·달력 탭 | 줄 긋고 남음 | 다시 누르면 해제 |
| 체크리스트 | 줄 긋고 남음 | 다시 누르면 해제 |

## 3. 기준 (`docs/UI_STANDARD.md` 초안)

같은 결과의 동작은 같게, 다른 결과의 동작은 다르게 한다. 문구를 하나하나 승인받지는 않는다. **뜻이나 정책이 바뀔 때만** 사용자에게 묻는다.

### 3.1 용어

| 개념 | 이름 | 쓰지 않음 |
|---|---|---|
| 할 일 | 할 일 | |
| 할 일 안의 긴 글 | **설명** | 메모 |
| 메모 기능 | 메모 | |
| Octopus 자체 달력 | **달력** | 캘린더 |
| 바깥 일정 | Google 캘린더 / Google 일정 | 구글 캘린더 |
| 요일마다 저절로 생기는 할 일 | **체크리스트** (하나하나는 '체크리스트 항목') | 루틴, 데일리 체크리스트, 오늘의 체크리스트 |
| 날짜 지난 미완료 | 지난 할 일 | 지난, 지난 미완료 |
| 안 하기로 한 할 일 | **안 하기로 함** | 취소 |
| 연결 도구에서 온 것 | 들어온 할 일 | 후보 |

### 3.2 동사

같은 결과면 같은 말, 다른 결과면 다른 말이다.

| 결과 | 이름 |
|---|---|
| 새로 만듦 | 추가 |
| 다른 것에서 만듦 | ○○로 만들기 (예: 할 일로 만들기) |
| 고친 것을 저장 | 저장 |
| 고치기 시작 | 편집 |
| 영구히 없앰 | 삭제 (확인 후) |
| 연결만 끊음 | 연결 끊기 |
| 하던 입력·확인을 그만둠 | 취소 |
| 할 일을 안 하기로 함 | 안 하기 |
| 대화상자·패널·알림을 치움 | 닫기 |
| 배치 모드 끝 | 배치 끝 |

### 3.3 동작

1. **한 줄 입력**(할 일 추가, 홈 메모 한 줄): Enter 는 저장이다. 한글 조합 중 Enter 는 무시한다.
2. **여러 줄 입력**(메모 화면, 설명): Enter 는 줄바꿈, Ctrl/Cmd+Enter 는 저장이다. [저장] 버튼을 항상 둔다.
3. **대화 입력**(지시하기): Enter 는 보내기, Shift+Enter 는 줄바꿈이다. 채팅의 관례를 따른다.
4. **할 일 추가**:
   - 자연어 해석은 어디서나 같고, 저장 전에 '알아들은 것'을 보여 준다.
   - 날짜 상세에서는 그 날짜가 기본이다. 문장에 날짜가 있으면 문장이 이긴다. 이 우선순위를 미리보기에 표시한다.
   - 시각 고르기 칸은 날짜 상세에 남긴다.
5. **추가한 결과**: 지금 보이는 목록에 안 나타나는 곳으로 갔으면 안내한다. 예: "수신함에 추가했어요 [보기]", "내일에 추가했어요 [보기]". 입력칸을 비우는 것만으로 성공을 알리지 않는다.
6. **체크 결과와 복구는 어디서나 같다**:
   - 체크하면 바로 줄이 그어진다(저장 의미는 똑같이 done).
   - 어느 화면에서든 같은 방법으로 되돌릴 수 있어야 한다. 다시 누르기, 또는 같은 모양의 되돌리기 알림이다.
   - 체크한 줄이 목록에서 어디로 가는지(남음·아래로·사라짐)는 화면 목적에 따라 다를 수 있다. 다만 그 화면 안에서는 늘 같다.
7. **떠나기 보호**: 쓰던 내용이 있으면 다음 상황에서 먼저 묻는다(버리기 / 계속 쓰기).
   - 다른 항목 선택, 닫기, 다른 화면 이동, 날짜 이동
   - 업데이트 재시작
   데이터가 바뀌었다고 화면이 초안을 버리지 않는다. 저장이 실패하면 입력은 그대로 남는다.
8. **저장은 확인한다**:
   - 저장이 실패하면 화면 값을 믿게 두지 않고, 짧은 오류와 [다시 시도]를 보여 준다.
   - 저장 중에는 같은 요청을 다시 보내지 않는다.
   - 늦게 온 응답이 더 최신 선택을 덮지 않는다.
9. **안 하기로 함**:
   - 완료와 섞지 않는다. 완료 수에도 넣지 않는다.
   - '완료' 보기 안에 [완료 | 안 하기로 함] 거르기를 둔다. 그곳에서 다시 열 수 있다.
   - 앱을 다시 켜도 찾을 수 있다.
10. **행 동작**:
    - 마우스를 올리거나 키보드 포커스가 오면 보인다.
    - 늘 보이는 '더보기(⋯)' 버튼도 하나 둔다(터치용).
    - 제목을 누르면 편집이다.
11. **글자**:
    - 설명문은 줄인다. 다만 연결 권한, 덮어쓰기, 재시작 설치, 반복 규칙, 되돌릴 수 없는 삭제의 짧은 안내는 남긴다.
    - placeholder 를 라벨 대신으로 쓰지 않는다. 입력칸마다 접근성 이름이 있어야 한다.
12. **보이는 화면과 저장 규칙**: 사용자가 '보관함'을 고르지 않는다.
    - 날짜를 넣으면 예정, 빼면 수신함이다.
    - '나중에'는 [나중에로] 버튼 한 번으로 보낸다.
    - 맞지 않는 조합은 오류 대신 저절로 맞춘다.

### 3.4 부품·디자인

- 할 일 입력은 `QuickInput` 하나(날짜 기본값·시각 칸은 선택 옵션)다. 여러 줄 입력은 공통 부품 하나다.
- 공통 부품은 수단이고 목표가 아니다. 달력·루틴 기록처럼 목적이 다른 화면은 모양이 달라도 된다. 3.3 의 결과와 복구 규칙만 지키면 된다.
- 색·글꼴은 `index.css` 토큰만 쓴다. `slate-*`·`indigo-*` 직접 사용은 검사 테스트로 막는다.

## 4. 실행 계획

**검증 원칙:** 모든 단계는 정상 동작 + 취소·실패·재시도·느린 응답·재시작을 테스트로 덮는다. 빌드한 앱에서 작은 창과 키보드로 확인하고 기록을 남긴다. 자동 테스트 통과를 화면 확인으로 치지 않는다.

### 1단계 — 데이터·실수 보호

| 항목 | 할 일 | 끝났다는 기준 |
|---|---|---|
| P1 | 할 일 탭·메모 화면에 떠나기 보호를 연결한다. `App` 의 `dataVersion` 재마운트를 없애고 각 화면이 스스로 다시 읽게 한다(홈·달력과 같게) | 편집 중 다른 항목·다른 화면·데이터 변경에서 초안이 남거나 먼저 묻는다. 테스트로 확인 |
| P2 | '완료' 보기에 [완료 \| 안 하기로 함] 거르기를 두고, 거기서 다시 열 수 있게 한다 | 안 하기 → 앱 재시작 → 찾아서 다시 열기 |
| P3 | 홈 '오늘 할 일' 카드에 체크 복구를 넣는다(3.3-6) | 홈에서 실수 체크 → 같은 자리에서 되돌림 |
| P4 | `useSetting` 이 저장 결과를 보고, 실패하면 알리고 다시 시도하게 한다. 늦은 응답이 최신 값을 덮지 않게 한다 | 저장 실패 가짜 응답·순서 뒤바뀐 응답 테스트 |
| P5 | 메모 저장 중 재요청을 막고, 저장한 글과 그 뒤 입력을 구분한다 | 느린 저장 중 Enter 연타 → 1건. 그사이 입력은 남음 |
| P6 | 업데이트 동작이 실패하면 알림 목록·설정에 짧은 오류와 [다시 시도]를 보인다. 설치 전에 쓰던 내용이 있으면 묻는다 | 실패 가짜 응답 테스트 |
| C1 | 달력 탭 날짜 이동을 한 번에 처리한다. 확인을 거절하면 달·선택·초안이 모두 그대로 | 테스트 |

### 2단계 — 추가·끝내기 흐름

| 항목 | 할 일 | 끝났다는 기준 |
|---|---|---|
| F3 | 추가 결과 안내 + [보기](그 할 일이 있는 보기로 가서 선택) | 홈에서 "보고서", "내일 보고서" → 안내 → 한 번 눌러 그 할 일 |
| F1 | 날짜 상세·달력 탭도 자연어 입력. 그 날짜가 기본이고 시각 칸은 유지 | "3시 회의" → 그 날 15:00. "내일 회의" → 미리보기에 내일로 표시 |
| F4 | 홈 할 일 제목 → 상세, 홈 메모 → 그 메모, 메모 → 할 일로 만들기 → 만든 할 일로 이동 | 최소 클릭으로 원래 작업 복귀 |
