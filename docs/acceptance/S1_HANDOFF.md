# S1 구현 지시 — 바로가기 타일과 명확한 편집

Codex / 2026-11-25. 이 문서는 다음 작업 준비용이다. C2 검토 후 별도 착수 지시를 받는다.

## 범위

- ATDT의 큰 아이콘·이름 중심 타일과 명확한 일반/편집 모드를 참고한다. Octopus 색상과 UI 문구 체계를 유지한다.
- 일반 모드는 카드 너비에 따라 열 수가 바뀌는 타일 격자다. 아이콘·이름·유형을 읽을 수 있게 표시한다.
- 편집 모드에서는 이름 수정/위아래 이동/삭제를 수행한다. 편집 조작으로 프로그램이 실행되지 않는다.
- 기존 사용자 순서와 데이터 모델을 유지한다. 그룹·임의 아이콘·파비콘 네트워크 조회는 추가하지 않는다.
- 새 링크/파일/폴더 추가와 이름 수정 시 실패 또는 진행 중 상태에서 입력을 지우지 않는다.
- 중복 클릭/Enter 반복에 의해 중복 등록·중복 이동이 생기지 않게 한다.
- 목록 읽기 실패는 빈 상태와 구분하고 다시 시도 가능해야 한다. 홈의 loadShortcuts가 실패를 빈 배열로 바꾸는 동작도 수정 범위다.
- 실행 파일 승인, 안전한 URL 검사, ID 기반 열기, 삭제 확인, 선택 대화상자 취소 동작을 보존한다.
- C2의 변경 이벤트가 입력 초안을 지우지 않는지 함께 검사한다.

## 검증

`dev2-home.md` S1-01~08을 기준으로 테스트를 먼저 작성한다.
기존 shortcutsCard/shortcutRepository/IPC/platform 테스트와 C1/C2 테스트를 유지한다.
관련 테스트 → 타입 검사 → 전체 테스트 → 빌드 → 새 홈/편집 화면 증거 순서로 확인한다.
실제 OS 프로그램을 여는 자동 테스트는 하지 않는다.
최소 창 크기에서 긴 이름, 편집 버튼과 저장/취소 버튼이 접근 가능한지 확인한다.

보고 후 Codex 검토를 기다린다. 사용자 데이터를 수정하거나 push/main 병합/릴리스하지 않는다.
