# C2 구현 지시 — 날짜별 조작과 입력 보존

Codex / 2026-11-25. C1 코드 검토와 관련 36개 테스트 재실행 통과 후 착수한다.
방향은 `../DEV2_PRODUCT_PLAN.md`, 인수 항목은 `dev2-home.md`의 C2-01~10이다.
실제 UI 인수는 도구 오류로 남아 있으며 최종 Q1에서 별도로 완료해야 한다.

## 구현 범위

1. 날짜 상세에서 제목과 선택 날짜를 확인하고 할 일을 추가한다. 날짜는 항상 명시적으로 전달한다. 제목 안의 자연어로 날짜를 암묵적으로 변경하지 않는다.
2. 선택 날짜의 할 일 완료·완료 취소를 제공한다. 저장 중 같은 동작을 중복 요청하지 않는다. 실패 시 상태를 성공처럼 바꾸지 않는다.
3. 기존 상세 편집 흐름을 재사용하여 날짜·시간·제목 등을 수정한다. 기존 반복·루틴 제한과 검증을 그대로 적용한다.
4. 변경 결과를 날짜 상세, 월간 요약, 오늘 카드, 할 일 목록에 반영한다. 홈 전체 재마운트로 갱신하지 않는다.
5. 작성 내용이 있으면 닫기/Esc/배경 클릭/다른 날짜 이동/화면 이동에서 유지하거나 버리기 확인을 제공한다. 저장 실패 시 내용 유지. 저장 중 추가 이동으로 다른 날짜에 저장되거나 늦은 응답이 새 입력을 지우지 않도록 한다.
6. `App.tsx`의 `key={dataVersion}`를 바꾸는 경우, 다른 화면의 갱신을 잃지 않도록 Task/Memo/Routine 화면도 기존 행동을 회귀 검증한다. 전역 이벤트가 홈 메모/바로가기 초안과 달력 선택 월·날짜를 지우면 안 된다.
7. 모달의 포커스 트랩은 추가될 textarea/select/취소 확인 버튼까지 포함해 확인한다. Ctrl+K 중첩 방지를 유지한다.

## 검증 순서

- C2 핵심 실패 테스트를 먼저 작성하여 현재 코드에서 실패함을 확인한다.
- UI→실제 IPC→임시 DB 연결을 활용한다. 호출 스파이만 통과시키지 않는다.
- 추가/연속 클릭/실패·재시도/취소 확인/완료·되돌리기/날짜 이동/반복·루틴/카드 간 갱신/전역 갱신 시 초안 보존을 검사한다.
- 파일 DB를 닫고 다시 열어 변경 유지 확인. 사용자 DB는 사용하지 않는다.
- 관련 테스트, typecheck, 전체 test, build 실행 후 결과를 인수 문서에 누적한다.
- 새 증거와 미확인 항목을 구분하여 보고한다. 기존 옵시디언 간헐 실패가 나오면 원인을 확인하고 관련 없는 제품 코드를 임의 변경하지 않는다.

새 그룹·외부 일정 편집·백업·원형 메뉴 전체 재설계는 추가하지 않는다.
완료 후 검토를 기다린다. S1은 Codex가 별도 지시한다. push/main 병합/릴리스는 하지 않는다.
