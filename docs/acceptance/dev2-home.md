# dev2 홈 개선 — 시스템·인수 테스트

작성: 2026-11-24 (Asia/Seoul)  
방향 문서: [DEV2_PRODUCT_PLAN.md](../DEV2_PRODUCT_PLAN.md)

## 1. 판정 규칙

- `미실행` / `통과` / `실패` / `차단`으로 구분한다.
- 자동 테스트, Electron 실제 동작, 사용자 확인을 별도로 기록한다.
- 기존 테스트 통과가 신규 기능 통과를 의미하지 않는다.
- 화면 캡처는 레이아웃 증거다. 저장·재시작·클릭 동작 증거를 대체하지 않는다.
- C1, C2, S1 각각의 필수 항목을 통과해야 다음 작업으로 이동한다.
- 모든 대상 항목의 자동 테스트와 실제 UI 검증이 끝나기 전 전체 인수 완료로 표시하지 않는다.
- 테스트를 생략하거나 기대 결과를 바꿔 실패를 없애지 않는다. 요구 변경은 방향 문서에 사유를 남긴다.

## 2. 안전한 검증 환경과 데이터

실제 사용자 DB와 ATDT 데이터는 건드리지 않는다. 임시 DB 또는 독립된 테스트 userData를 사용한다.
자동 테스트는 날짜를 고정하고, Google·파일 열기·실행 파일 승인은 가짜로 대체한다.
기존 `tests/renderer/backend.ts`의 실제 저장소/IPC를 활용한다.

기준 날짜 T=2026-11-24, 테스트 시각은 명시적으로 로컬 날짜로 만든다.

| 데이터 | 설정 |
|---|---|
| A | T일 09:00, 미완료 할 일 |
| B | T일 시간 없음, 미완료 할 일 |
| C | T+1일 14:00, 미완료 할 일 |
| D | T-1일, 지난 미완료 |
| E | 예정 날짜 T-1일, 실제 완료 시각 T일인 완료 항목 |

## 7. 검증 명령 및 기록 양식

저장소 루트 `C:\Users\tta\octopus`에서 PowerShell로 실행한다.

```powershell
npm run typecheck

npm run build
```

새 테스트는 먼저 해당 파일만 실행해 실패→구현→통과를 확인하고, 통합 시 전체 테스트를 실행한다.
